# 🎮 FreeFire-Core: خادم اللايكات ومولد الحسابات المتكامل

[![Automated CI Test Suite](https://github.com/userkxm00/FreeFire-Core/actions/workflows/tests.yml/badge.svg)](https://github.com/userkxm00/FreeFire-Core/actions/workflows/tests.yml)

> **مستودع احترافي ونظيف** يجمع بين نظام زيادة لايكات فري فاير (Like API) ومحرك إدارة الحسابات والتوكنات، مع لوحة تحكم ويب تفاعلية، وتحقق صارم من المدخلات، واختبارات آلية CI/CD، ومطابقة معايير أمان الويب (CSRF Protection, HttpOnly Sessions, Zero Leakage).

---

## 📌 1. نظرة عامة (Overview)

المشروع عبارة عن منصة متكاملة:
1. **خادم REST API (Flask)**:
   - يدير طلبات زيادة اللايكات عبر `GET /like`.
   - محمي بمفتاح أمان يدعم:
     - Header: `X-API-Key: YOUR_KEY`
     - Header: `Authorization: Bearer YOUR_KEY`
     - *(ملاحظة أمنية: تم حظر تمرير المفتاح عبر Query Params `?key=` نهائياً لمنع تسريبه في السجلات والروابط)*.
   - تحقق صارم من صحة معرف اللاعب (UID) وصيغة التوكنات (JWT Format).
   - عداد استخدام يومي محمي بـ Thread-Lock وكتابة ذرية (Atomic Write) مع تعافي تلقائي من أخطاء الـ JSON.
2. **لوحة تحكم تفاعلية مؤمّنة (Web Dashboard)**:
   - متاحة مباشرة عبر المتصفح على `http://127.0.0.1:5000/`.
   - تسجيل دخول مشفر عبر `POST /login` مع حماية CSRF كاملة.
   - كوكيز جلسة موقعة وآمنة (`HttpOnly`, `SameSite=Lax`, `Secure` على HTTPS).
   - انعدام تسريب المفاتيح: كود الـ JavaScript والـ HTML لا يحتوي إطلاقاً على أي أسرار؛ المتصفح يتواصل عبر كوكيز الجلسة المشفرة.
3. **محرك إدارة التوكنات والجسر (`generator_bridge.py`)**:
   - يدعم استخراج التوكنات، وحفظها تلقائياً بدون تعارض في المفاتيح (`token` و `jwt_token`).
   - تنظيف تلقائي للذاكرة (TTL) لمنع تسريب الذاكرة في المهام الطويلة.
4. **حزمة اختبارات آلية ومسار CI/CD (`tests/test_suite.py`)**:
   - 19 اختباراً آلياً مدمجاً مع GitHub Actions للتحقق المستمر عند كل Commit.

## 🌐 3. واجهات وبرمجة الـ API (Endpoints Reference)

### 🔐 سياسة المصادقة والأمان (Security & Authentication Policy)
* **لوحة التحكم (Web UI):** تستخدم جلسات مشفرة آمنة (Flask Signed Sessions) مع ملفات تعريف ارتباط `HttpOnly` و `SameSite=Lax`. يتم تسجيل الدخول عبر `POST /login`، ولا يتم تسريب المفتاح في الروابط أو داخل كود الـ JavaScript.
* **واجهات REST البرمجية (Bots & Scripts):** يجب إرسال مفتاح الـ API حصرياً عبر الهيدر:
  - `X-API-Key: YOUR_SECRET_KEY`
  - أو `Authorization: Bearer YOUR_SECRET_KEY`
* **منع تمرير المفتاح في الرابط:** طلبات `?key=...` مرفوضة نهائياً (`401 Unauthorized`) لمنع تسريب المفاتيح في سجلات الخوادم وسجل المتصفح.

---

### 1) إرسال اللايكات (`GET /like`)
* **الرابط:**
  ```text
  GET /like?uid=12747380350&region=ME
  Headers: X-API-Key: YOUR_KEY
  ```
* **التحقق:**
  - `uid`: يجب أن يكون رقماً بين 7 و 15 خانة.
  - `region`: يجب أن يكون من السيرفرات المعتمدة (ME, BD, IND, BR, SAC, ID, VN, TH, PK, CIS, SG, TW).

---

### 2) إضافة توكنات مباشرة (`POST /tokens/add`)
* **الرابط:**
  ```text
  POST /tokens/add
  Headers: X-API-Key: YOUR_KEY
  Content-Type: application/json
  ```
* **Body:**
  ```json
  {
    "region": "ME",
    "tokens": "eyJhbGciOiJIUzI1NiJ9..."
  }
  ```
* **التحقق وتوضيح مهم حول JWT:**
  - يتم فحص بنية التوكن (3 أجزاء تبدأ بـ `ey`) وتفكيك حمولة الـ Payload دون تحقق تشفيري لفحص انتهاء الصلاحية (`exp`).
  - **تنبيه:** هذا الفحص هو فحص هيكلي وزمني محلي فقط، ولا يثبت أن التوكن موقع رسمياً من جارينا أو أنه غير محظور، حيث أن التحقق من التوقيع التشفيري يتطلب مفاتيح جارينا الخاصة.

---

### 3) توليد التوكنات (`GET` أو `POST /generate`)
* **الرابط:**
  ```text
  POST /generate
  Headers: X-API-Key: YOUR_KEY
  Body: {"region": "ME", "count": 10, "async": true}
  ```
* **ملاحظة حول إصدار التوليد:**
  - حزم TSun الثنائية (`MajorRegister` و `MajorLogin`) ومصفوفات التشفير مبنية أصلاً على إصدار **OB53** (`1.114.13`)، بينما خوادم Free Fire الحالية في **OB55+**.
  - ظهور خطأ 500 في `MajorRegister` مؤشر على عدم التوافق، لكنه قد ينتج عن أي من: اختلاف بنية Protobuf، أو فحص البصمات، أو حظر خوادم Garena لطلبات البروكسيات، ولا يجوز الجزم بسبب واحد دون تحليل شامل ومصرح لحزم اللعبة الرسمية.

---

### 4) فحص رصيد التوكنات (`GET /tokens/status`)


## ☁️ 4. ملاحظات النشر والتخزين (Vercel & Serverless)

* **طبيعة بيئة Vercel:** بيئات Serverless تمتلك نظام ملفات مؤقت وقابل للإزالة (Ephemeral Filesystem). ملفات الـ JSON المحلية (`usage_state.json` و `token_*.json`) تُمسح أو يُعاد ضبطها عند إعادة تدوير الحاويات.
* **متطلبات الإنتاج السحابي:** لنشر النظام بشكل دائم على Vercel أو المنصات المشابهة، يجب استبدال التخزين المحلي بقاعدة بيانات خارجية دائمة:
  - للتوكنات والعداد: **Redis / Upstash** أو **PostgreSQL / Supabase**.
  - لمهام التوليد في الخلفية: مهام Vercel تنتهي بانتهاء الاستجابة (Timeout)، وتتطلب مهام التوليد الطويلة استضافة على خادم دائم (VPS) أو وسيط مهام غير متزامن (Celery / BullMQ / QStash).

## ⚠️ 6. توضيح تقني صريح حول بروتوكول جارينا (Upstream Reality)

* **ما تم إثباته واختباره بنجاح:**
  - عمل خادم Flask الداخلي، حماية الجلسات، كوكيز `HttpOnly`، فحص CSRF، ورفض المفاتيح في الروابط.
  - جاهزية نقاط النهاية (`/like`, `/tokens/add`, `/remain`, `/tokens/status`).
  - تشفير الـ UID وحزم الـ Protobuf.
  - إمكانية إرسال اللايكات بنجاح بمجرد تزويد الخادم بتوكنات صالحة (JWT) عبر لوحة التحكم.
* **ما لم يُحل أو يثبت عمله بعد:**
  - التوليد التلقائي للتوكنات (TSun Engine) يواجه رفضاً من خوادم جارينا (`MajorRegister 500`).
  - الحزم الثنائية في TSun مبرمجة على إصدار OB53 القديم (`1.114.13`) وتتطلب تحديثاً شاملاً لبصمات APK وتواقيع العميل للتوافق مع سيرفرات OB55 الحالية.
  - لا يُدعى أبداً أن التوليد التلقائي أو المشروع جاهز للإنتاج بنسبة 100% دون تحديث تلك البصمات وربط قاعدة بيانات سحابية.
